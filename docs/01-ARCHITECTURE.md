## Поток данных

1. **App.tsx** хранит `GameState` как React state
2. Действия пользователя вызывают функции из `GameEngine`
3. `GameEngine` мутирует состояние (для производительности)
4. App создаёт новый объект состояния (`{...state}`) для React re-render
5. UI компоненты получают состояние через props

## Почему не сервер?

Данная среда (Vite → статический билд) не поддерживает запуск серверного процесса.
Реализованы два режима:
- **Hot-seat**: оба игрока на одном устройстве
- **AI**: однопользовательский режим

Для полноценного мультиплеера по сети можно добавить:
- Node.js + WebSocket сервер
- PeerJS для P2P
- Firebase Realtime DB

## Состояние игры

```typescript
interface GameState {
  players: [Player, Player];     // Два игрока
  currentPlayerIndex: 0 | 1;     // Чей ход
  turnNumber: number;             // Номер хода
  phase: 'mulligan' | 'playing' | 'gameOver';
  winner: number | null;          // Победитель
  log: string[];                  // Лог действий
}
```

## Валидация действий

Все действия проходят через функции GameEngine:
- `playCard()` проверяет: ману, тип карты, заполненность поля
- `attack()` проверяет: может ли атаковать, провокацию, цель
- `endTurn()` переключает активного игрока
- `useHeroPower()` проверяет: ману, использование

## AI

AI использует жадную стратегию:
1. Разыгрывает самые дорогие карты
2. Атакует существ с максимальной атакой
3. Использует способность героя
4. Завершает ход
