# ЭТАП 0: АНАЛИЗ И ПЛАНИРОВАНИЕ

## 1. Анализ задачи

### Подзадачи:
1. **Игровая логика** — ядро игры (ходы, мана, карты, атака, здоровье)
2. **Система карт** — 30 уникальных карт с эффектами и ключевыми словами
3. **Сетевой слой** — мультиплеер по локальной сети
4. **UI/UX** — пиксельный интерфейс, все экраны
5. **Анимации** — плавные переходы, эффекты атак, заклинаний
6. **Звуки** — 8-bit звуковые эффекты через Web Audio API
7. **Эмоции** — система эмоций как в Hearthstone
8. **Документация** — README, описание карт, протокол

### Риски:
- Ограничение среды: статический билд (Vite → dist/index.html), нет возможности запустить отдельный Node.js сервер
- Решение: использовать PeerJS (WebRTC) для P2P соединения между двумя браузерами
- Альтернатива: hot-seat режим (два игрока на одном устройстве) + AI противник
- Сложность баланса 30 карт
- Производительность анимаций на слабых устройствах

## 2. Выбор технологий

### Frontend: React + TypeScript + Tailwind CSS
- **Обоснование**: Уже настроен в проекте. React обеспечивает компонентную архитектуру, TypeScript — типобезопасность, Tailwind — быстрый UI.
- **Рендеринг**: DOM + CSS анимации + Framer Motion. Canvas избыточен для карточной игры.

### Сеть: PeerJS (WebRTC)
- **Обоснование**: P2P соединение без необходимости в отдельном сервере. PeerJS предоставляет бесплатный signaling сервер. Работает в локальной сети и через интернет.
- **Альтернатива**: BroadcastChannel (только вкладки одного браузера) — слишком ограничено.

### Анимации: Framer Motion + CSS Transitions
- **Обоснование**: Framer Motion уже в зависимостях. Отлично работает с React, поддерживает layout animations, gestures.

### Звуки: Web Audio API
- **Обоснование**: Генерация 8-bit звуков программно, без внешних файлов. Малый размер, мгновенная загрузка.

### Шрифт: Press Start 2P (Google Fonts)
- **Обоснование**: Классический пиксельный шрифт, бесплатен, хорошо читается.

### Разделение ответственности:
- **Game Engine**: вся игровая логика, валидация действий, состояние игры
- **Network Layer**: синхронизация между игроками, P2P соединение
- **UI Components**: отображение состояния, отправка команд
- **Audio Engine**: генерация и воспроизведение звуков

### Хранение состояния:
- Хост (создатель комнаты) является "авторитетным" — хранит полное состояние игры
- Клиент отправляет команды (play card, attack, end turn)
- Хост валидирует и рассылает обновления

## 4. Структура данных

```typescript
// Типы карт
type CardType = 'minion' | 'spell' | 'weapon';
type Rarity = 'common' | 'rare' | 'epic' | 'legendary';
type Keyword = 'taunt' | 'charge' | 'divine_shield' | 'poisonous' | 
               'battlecry' | 'deathrattle' | 'windfury' | 'lifesteal';

interface Card {
  id: string;
  name: string;
  type: CardType;
  cost: number;
  rarity: Rarity;
  description: string;
  flavorText: string;
  keywords: Keyword[];
  // Для существ
  attack?: number;
  health?: number;
  // Для заклинаний
  spellEffect?: SpellEffect;
  requiresTarget?: boolean;
  // Для оружия
  weaponAttack?: number;
  weaponDurability?: number;
  // Эффекты
  battlecryEffect?: Effect;
  deathrattleEffect?: Effect;
  staticEffect?: StaticEffect;
}

interface BoardMinion {
  instanceId: string;
  cardId: string;
  currentAttack: number;
  currentHealth: number;
  maxHealth: number;
  canAttack: boolean;
  hasAttacked: boolean;
  keywords: Keyword[];
  hasDivineShield: boolean;
  isPoisonous: boolean;
  hasTaunt: boolean;
  hasWindfury: boolean;
  attacksThisTurn: number;
}

interface Player {
  id: string;
  name: string;
  heroHealth: number;
  maxMana: number;
  currentMana: number;
  deck: Card[];
  hand: Card[];
  board: BoardMinion[];
  weapon?: WeaponState;
  fatigue: number;
}

interface GameState {
  players: [Player, Player];
  currentPlayerIndex: 0 | 1;
  turnNumber: number;
  phase: 'mulligan' | 'playing' | 'gameOver';
  winner?: 0 | 1;
  history: GameAction[];
}

interface GameAction {
  type: 'play_card' | 'attack' | 'end_turn' | 'hero_power';
  playerId: string;
  data: any;
  timestamp: number;
}

// Сетевые сообщения
type NetworkMessage = 
  | { type: 'create_room'; roomId: string }
  | { type: 'join_room'; roomId: string }
  | { type: 'player_ready' }
  | { type: 'game_start'; initialState: GameState }
  | { type: 'action'; action: GameAction }
  | { type: 'state_update'; state: GameState }
  | { type: 'emotion'; emotion: EmotionType }
  | { type: 'disconnect' }
  | { type: 'chat'; message: string };
```

## 5. Сетевой протокол

### Сообщения клиент → сервер (хост):
| Тип | Описание | Данные |
|-----|----------|--------|
| `create_room` | Создание комнаты | roomId |
| `join_room` | Присоединение | roomId |
| `player_ready` | Готовность | - |
| `play_card` | Разыграть карту | cardId, targetId? |
| `attack` | Атака | attackerId, targetId |
| `end_turn` | Завершить ход | - |
| `emotion` | Эмоция | emotionType |

### Сообщения сервер (хост) → клиент:
| Тип | Описание | Данные |
|-----|----------|--------|
| `room_created` | Комната создана | roomId, hostId |
| `player_joined` | Игрок зашёл | playerId, playerName |
| `game_start` | Игра началась | initialState |
| `state_update` | Обновление состояния | fullState |
| `game_over` | Игра окончена | winnerId |
| `emotion` | Эмоция от противника | emotionType |
| `error` | Ошибка | message |

### Обработка проблем:
- **Обрыв соединения**: 10 секунд на переподключение, затем поражение
- **Десинхронизация**: хост всегда прав, клиент запрашивает полное состояние
- **Переподключение**: при reconnect отправляется запрос sync, хост шлёт полное состояние
